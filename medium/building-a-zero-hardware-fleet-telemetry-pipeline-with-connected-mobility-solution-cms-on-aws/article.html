Modern vehicles already ship with embedded telematics units (TCUs). By leaning on those factory modems — rather than bolting-on aftermarket gateways — Fleet Operators can ingest rich, near-real-time data straight into the AWS Cloud. The Connected Mobility Solution on AWS (CMS) gives you two drop-in modules that cover the critical first mile (ingest & storage) and the last mile (visualisation):

High-level Architecture

How the pieces fit together

  1. Embedded TCU publishes data — Each OEM vehicle pushes encrypted MQTT messages (position, odometer, DTCs, driver ID) over its factory modem.
  2. AWS IoT Core authenticates the device and fan-outs the stream via three IoT Rules: two for storage, one for alerts. AWS Documentation
  3. Connect & Store
  • Rule #1 → Amazon S3 (raw JSON).
  • Rule #2 → Firehose → AWS Glue job → Parquet in S3 (analytics-optimised).
  • Rule #3 → CMS Alerts API (e-mail/SMS/Slack).
  1. Glue Crawler catalogues every Parquet partition so analysts can query live data in Athena without ETL.
  2. CMS UI pulls metrics through a lightweight API (Lambda + API Gateway) and renders:
  • Fleet map with real-time locations
  • Vehicle health widgets (fuel, battery, MIL status)
  • Driver scorecards and downloadable reports

Typical Phase-1 rollout

  1. Deploy CMS UI & Connect & Store (approx. 90 minutes per account via Backstage).
  2. Register vehicles through the CMS portal or Bulk-VIN import.
  3. Enable OEM API subscriptions (no-code consent flow for BMW, Mercedes, Toyota, etc.).
  4. Configure first FleetWise campaign for the test cohort; validate data landing in S3.
  5. Launch driver-score report in QuickSight and share with Ops leadership.

Call to action

By leveraging CMS’s pre-built modules, Fleet Operators can stand up a production-grade connected-vehicle program without touching a single CAN bus or lifting a wrench. The result: faster insights, safer drivers, and a future-ready data foundation — delivered on AWS economics.
