1) What you’re building (in one line)

A serverless system where candidates call a number, answer structured prompts, get automatically transcribed and scored for English speaking skill and communication quality, and the results show up in a recruiter dashboard with audio, transcript, scores, and exports.

2) Core business use cases

High-volume pre-screening

  • Auto-score fluency, pronunciation, grammar, vocabulary, coherence.
  • Route only top candidates to live interviews → reduce recruiter load 50–80%.

BPO / Contact-center hiring

  • Role-aligned scenarios (angry customer, billing explanation).
  • KPIs: pass-through %, average speaking WPM, silence %, filler rate, call time.

Campus / gig / seasonal hiring

  • Self-service phone screening at scale (24×7), instant results and exports.

Language proficiency benchmarking

  • Consistent leveling (A2–C2-like bands) across regions.
  • Track improvement over time for internal mobility or L&D.

Compliance & fairness

  • Redaction, opt-in consent, explainable rubric, periodic human audit.

Primary KPIs: pass rate, time-to-decision, recruiter minutes saved, rubric drift, ASR word error rate (WER), appeal rate, SLA success.

3) AWS serverless reference architecture

Key services:

  • Telephony & IVR: Amazon Connect (+ optional Lex for prompts/branching)
  • Speech analytics: Amazon Transcribe Call Analytics (or Connect Contact Lens)
  • Orchestration: EventBridge → Step Functions → AWS Lambda
  • Scoring AI: Amazon Bedrock (e.g., Claude 3.5 / Llama 3.1) + Comprehend (signals)
  • Storage: S3 (audio/transcripts/artifacts), DynamoDB (sessions & scores)
  • Search/analytics: OpenSearch Service (transcripts), Athena/Glue (ad-hoc SQL), QuickSight (dashboards)
  • App/API/Auth/CDN: API Gateway + Lambda, Cognito, CloudFront (+ S3 static)
  • Notifications & Integrations: SNS/SES, EventBridge to ATS webhooks
  • Security: KMS, IAM, WAF (on CloudFront)

4) Detailed technical design

4.1 Data model (serverless-friendly)

DynamoDB (single table): VoiceScreening

  • PK = ORG#<orgId>; SK varies by entity.

Entities

  • Candidate Session: SK = SESSION#<sessionId>
  • orgId, candidateId, phone, locale, startTime, endTime, status
  • s3AudioUri, s3TranscriptUri, featuresVersion
  • Scores: SK = SCORE#<sessionId>#v<version>
  • rubric (weights), dimensionScores, overallScore, rationale, confidence
  • llmModel, llmPromptHash, metricsHash
  • Metrics (objective): SK = METRICS#<sessionId>
  • wpm, silencePct, overlapPct, fillerPerMin, ttr, pausesP95, asrWER
  • Audit/Appeals: SK = APPEAL#<sessionId>#<appealId>

GSIs

  • GSI1 (by candidate): PK = CANDIDATE#<candidateId>, SK = SESSION#<startTime>
  • GSI2 (by status/time): PK = STATUS#<status>, SK = <startTime>

S3 layout

s3://<bucket>/
  raw/
    connect/<date>/<contact-id>.wav
    transcribe/<date>/<contact-id>.json
  features/<session-id>/metrics.json
  scoring/<session-id>/llm_input.json
  scoring/<session-id>/llm_output.json
  exports/<date>/scores.csv

OpenSearch index: transcripts

  • sessionId, orgId, text, timestamps[], sentences[], entities[], piiRedacted:bool

4.3 Metrics Lambda (objective features)

Inputs: transcript JSON (words with timestamps), channel separation, confidence Outputs:

  • WPM (exclude pauses): words / speaking minutes
  • Silence%: total non-speech duration / call duration
  • Filler rate: (“um”, “uh”, “like”, “you know”) per minute
  • Type-token ratio (TTR): unique words / total words
  • Pauses P95: 95th percentile pause length
  • ASR WER (if you have reference; else use avg confidence)

Pseudocode (Python)

def compute_metrics(transcript):
    words = [w for w in transcript["items"] if w["type"]=="pronunciation"]
    durations = transcript["utteranceSegments"]  # or compute from timestamps
    speaking_time = sum(seg["duration"] for seg in durations if seg["speaker"]=="candidate")
    total_time = transcript["jobSummary"]["durationInSeconds"]
    wpm = (len(words) / max(speaking_time, 1e-6)) * 60
    silence_pct = max(0.0, 1 - speaking_time / max(total_time, 1e-6))
    fillers = {"um","uh","erm","like","you know"}
    filler_rate = sum(1 for w in words if w["content"].lower() in fillers) / (max(total_time,1e-6)/60)
    vocab = set(w["content"].lower() for w in words if w["content"].isalpha())
    ttr = len(vocab) / max(len(words), 1)
    pauses = compute_pauses(words)
    pauses_p95 = percentile(pauses, 95)
    return dict(wpm=wpm, silencePct=silence_pct, fillerPerMin=filler_rate, ttr=ttr, pausesP95=pauses_p95)

4.4 Rubric & LLM scoring (Bedrock)

Dimensions & weights (example)

  • Fluency 0.25, Pronunciation 0.20, Vocabulary 0.20, Grammar 0.20, Coherence 0.15
  • Return 0–100 per dimension + overall (weighted) and explanatory rationale + confidence.

Prompt template (system) “You are a certified assessor of spoken English for hiring pre-screening. Score the candidate response fairly and consistently by applying the rubric. Consider objective metrics provided (WPM, silence%, filler rate, TTR, pauses P95), transcript content, and question intent. Avoid demographic, accent or identity bias. Exclude personal data. Output strictly in the JSON schema.”

Prompt (user)

Question: {{question_text}}
Transcript: {{transcript_text}}
ObjectiveMetrics: {{metrics_json}}
Rubric:
- Fluency: rate, flow, fillers, pauses
- Pronunciation/Intelligibility: clarity of words; understandable with minimal strain
- Vocabulary: appropriateness, range, precision
- Grammar: tense, agreement, articles/prepositions, sentence structure
- Coherence: relevance, logical structure, conclusions
Return JSON:
{
  "scores": {
    "fluency": 0-100,
    "pronunciation": 0-100,
    "vocabulary": 0-100,
    "grammar": 0-100,
    "coherence": 0-100
  },
  "overall": 0-100,
  "rationale": "2-4 sentences, concrete, reference transcript",
  "confidence": 0-1
}

Post-processing Lambda

  • Validate schema, clamp to [0,100], recompute overall from weights, store scores_vX.

4.5 Amazon Connect / IVR design

Contact flow blocks

  1. Play prompt (greeting + consent) → if no, hang up & mark status=DECLINED.
  2. Set logging + recording (enable redaction if using Contact Lens).
  3. Ask question 1 (“Describe a recent challenge… You have 60 seconds.”)
  4. Wait/Silence detection (reprompt once).
  5. Ask question 2/3 (role-specific scenarios).
  6. Thank you → end call.
  7. S3 recording + Call Analytics job → EventBridge → Step Functions.

Optional: Use Lex for dynamic branching (e.g., if candidate chooses role “Support Agent,” use that question set).

4.6 API design (API Gateway + Lambda)

  • GET /orgs/{orgId}/sessions?status=COMPLETED&from=... → list sessions (paginated)
  • GET /orgs/{orgId}/sessions/{sessionId} → scores, metrics, artifacts
  • GET /orgs/{orgId}/sessions/{sessionId}/audio → pre-signed S3 URL
  • POST /orgs/{orgId}/exports → create CSV in s3://.../exports/...
  • POST /webhooks/ats → Greenhouse/Lever updates (EventBridge buses)
  • Auth via Cognito JWT (groups: Admin, Recruiter, Viewer)

4.7 Frontend (Next.js)

Pages: /login, /sessions, /sessions/{id}, /exports

Components:

  • Waveform audio (peaks from S3 via pre-signed)
  • Transcript viewer with time-sync highlight
  • Scorecards per dimension + rationale text
  • Filters (score thresholds, date, role)
  • Export (CSV), Appeal (human review flag)

4.8 Analytics & search

  • OpenSearch: transcript full-text, filters by score/status/role/org.
  • QuickSight on Athena over S3 (scores, funnel, cohort by campaign/role/region).
  • Drift watch: track mean scores per month & alert if shifts > threshold.

5) Security, privacy, compliance

  • Consent capture (IVR prompt; store consent=true on session).
  • PII redaction in Transcribe/Contact Lens; store redacted transcript for UI; keep original in restricted prefix.
  • Encryption: S3, DynamoDB, OpenSearch all CMK-encrypted (KMS).
  • Least privilege IAM: Lambda roles scoped to prefixes like s3://bucket/raw/ and s3://bucket/scoring/.
  • Lifecycle: move audio/transcripts to Glacier after 30–60 days.

Lifecycle policy (S3)

{
  "Rules": [
    {
      "ID": "archive-audio",
      "Filter": { "Prefix": "raw/" },
      "Status": "Enabled",
      "Transitions": [{ "Days": 30, "StorageClass": "GLACIER" }],
      "Expiration": { "Days": 365 }

}
  • Guardrails for Bedrock: block disallowed topics; bias filters.
  • Right to be forgotten: delete S3 + purge OpenSearch + remove DDB items (use a DeleteSession Lambda).
  • WAF on CloudFront (SQLi/XSS, IP allowlists for admin).

6) CI/CD (CDK) & environments

  • Mono-repo: infra/ (AWS CDK Python/TS), services/ (Lambdas), web/ (Next.js).
  • Pipelines: GitHub Actions → cdk synth → cdk deploy to dev/stg/prod.
  • Config via SSM Parameter Store / Secrets Manager.
  • Canaries: CloudWatch Synthetics for API health.
  • Alarms: error rates, Step Functions failures, 95p scoring latency.

7) Cost notes (order-of-magnitude)

  • Connect minutes + Transcribe Call Analytics per minute dominate runtime cost.
  • Bedrock: LLM tokens for scoring; control by summarizing transcript to key points if lengthy.
  • DynamoDB on-demand, S3 pennies/GB, OpenSearch sized to QPS (or deploy serverless).
  • QuickSight reader-based pricing.

Tactics: batch scoring, shorter prompts, compress audio, retain 16kHz mono, archive aggressively.

8) Rollout plan (MVP → Scale)

  1. MVP (2–3 sprints)
  • Connect number + 3-question IVR, Transcribe batch, Step Functions, scoring Lambda (Bedrock), DDB, simple Next.js page.

2. Pilot (1–2 weeks)

  • Add OpenSearch, exports, QuickSight, ATS webhook, WAF rules, lifecycle.
  • Calibrate rubric on 100–300 labeled calls; align thresholds.

3. Scale

  • Multilingual routing, role-adaptive prompts, bias audits, human-in-the-loop appeals, serverless OpenSearch, org multi-tenanting, SSO.

9) Integration patterns (ATS/HRIS)

  • EventBridge outbound on ScoringCompleted with payload: orgId, sessionId, email/phone hash, overall, per-dim scores, link.
  • Webhooks to Greenhouse/Lever; S3 exports nightly to data lake.
  • SSO via Cognito federation (SAML/OIDC).

10) Acceptance tests & QA

  • Golden set of transcripts with expected scores (per dimension).
  • Stress 1k concurrent calls — monitor Transcribe quotas (request increases).
  • Latency budget: goal <5 min from call end to score available.
  • Fairness checks: compare distributions across geo/time; run inter-rater reliability vs human graders.
